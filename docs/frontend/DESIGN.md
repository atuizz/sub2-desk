# 前端设计约束

## 产品与视觉

Sub2 Desk 是对接原版 Sub2API 的独立桌面式 Web 控制台。主要用户是 API 使用者和后台运营者。以 macOS 桌面、图标、壁纸、窗口结构作为交互参考，但产品品牌、发布素材和法律定位保持独立。

保留：Dock、菜单栏、交通灯、多窗口、半透明外壳和应用启动动画。内容区域优先可读性：中性浅灰/深灰底、清楚的分隔、稳定表格、蓝色主操作。不要将整个业务内容区都改成高透明玻璃。

用户已明确否定简化线框图标替换：本地体验必须保留既有 macOS 风格图标的光影、细节和原有壁纸。独立可分发素材通过 release 构建选项使用，不得为打包方便改掉默认视觉基线。

层级：桌面背景 → 桌面信息 → 窗口外壳 → 工具栏 → 内容 → 附着弹层。高亮只用于当前焦点、选中项、主操作和状态。阴影柔和、有层次，不使用多层彩色发光边缘。

## 必须保持的行为

1. 打开/聚焦/最小化/还原/最大化/关闭行为一致。窗口不能超出可操作区域；小屏优先单窗口可达性。
2. 拖拽和缩放跟手，只对进入/退出和状态切换设置动画，不能给每次位置更新添加 transition-all。
3. 弹层附着所属窗口；只有最上层活动弹层能接收 Enter/Escape。提交中不得重复确认，键盘焦点不能落到后层。
4. Dock 在小屏不溢出；隐藏的 App 可从启动台找到；按钮和应用入口可用键盘操作。
5. 加载、空、错误、无权限、过期状态分别表达。后台失败不得生成余额、用量、延迟或健康状态。
6. 真实业务数据来自既有 API。所有 API 字段、路径、金额单位以现有契约为准；视觉改造不能悄悄改变业务行为。
7. 支持浅色/深色、减少动画、长标题、390px 窄屏和桌面分辨率。

## 组件和代码边界

- `mac-ui-core`：只承载窗口、组件、交互、主题，不引入业务 API、Pinia auth 或演示用户。
- `sub2-console`：应用注册、身份、业务 API、具体页面。
- `src/dev/`：仅开发环境组件预览。允许明确标记的样例数据，不进入线上认证/业务数据源。
- 优先改善已有组件，不另造同功能 Modal/Button/Table。新增组件必须先证明至少两个实际使用场景或独立预览价值。
- 主题、间距、圆角使用既有变量；修改共享变量须同时检查 Accounts、Dashboard 和弹层。

## 验收

至少检查：1440×900 浅色/深色、390×844；打开多个窗口、缩小视口、拖拽、最大化还原、切换焦点；弹层 Tab/Enter/Escape 与重复提交；后台失败的错误状态。

验收截图只能作为视觉证据，关键操作必须实际执行。模拟数据检查与真实后端检查分开记录。界面上只留用户需要的内容，工程说明放到文档或组件预览工具。
