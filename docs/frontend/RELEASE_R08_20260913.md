# R08 前端可靠性与小铺设置收口

本轮承接用户要求：补齐跨刷新防重、草稿保护，并改善截图中的“小铺与兑换”布局。保持Vue 3、Pinia、官方Sub2API契约和原有macOS风格。不改server、真实配置或业务数据。真实支付和邮件联调按用户要求不作为本轮收口条件。

## 小铺与设置

小铺配置采用独立页头和紧凑的分组容器：店铺身份、域名和打开方式放在同一标题行；名称与地址输入顶端对齐；移除作为次级操作，添加入口位于页头，重新读取和保存集中在底部。详细访问说明折叠展示。侧栏复用网上小铺独立图标。空态、读取失败、未保存、保存中和非法地址均有明确反馈；没有改变既有catfk/16688内嵌及其他链接外部打开规则。

小铺和请求策略在首次访问后保持挂载，切换分类不会丢草稿。小铺重新读取须显式确认丢弃修改。设置主表单依据已读快照比较差异；网关/面板限流/S3/图片存储/备份计划在读取或成功保存时更新各自基线，切分类时保留已修改的值。已加载的用户名、通知阈值、待提交密码/邮箱/头像等也纳入窗口保护。即时生效的外观与音量、搜索筛选不算未保存表单。无关模块的读取失败不再跨分类展示在小铺页。

## 桌面草稿保护与付款防重

共享保护通过所属窗口注册dirty/busy状态；红灯、菜单、快捷键和整桌面离开动作集中处理，放弃前需要明确确认，提交中不能放弃。隐藏分类和最小化窗口仍保留保护；刷新/离开页使用浏览器原生beforeunload确认。认证失效的强制清理独立处理，不让旧草稿阻止权限撤销。具体接线与场景证据在output/r08-closeout/drafts.md。

退款和收款提供方使用不含请求正文或密钥的持久化操作标记。跨窗口/刷新保留待核对状态；重新读取本身不自动解除未知结果保护；成功、明确拒绝或显式核对后才能恢复写入。账户与迟到响应隔离、多标签写入协调、存储失败禁止无保护写入，以及正常令牌续期的兼容性均按专项反例验证。具体流程与浏览器边界在output/r08-closeout/payment.md。
