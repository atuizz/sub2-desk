# Windows 本地启动与升级资料

本项目发行包只包含前端，不自带后端程序、数据库、Redis或真实配置。

已有本地实例默认目录为`output/backend-runtime`，必须包含`sub2api.exe`和`config.yaml`。`scripts/start-all.ps1`不再使用旧`server/`或根目录`sub2api-server.exe`。运行时目录也可显式传入；不会自动移动、覆盖现有配置。

```powershell
# 只读检查：显示目录、版本、运行状态，不启动或停止进程。
.\scripts\start-all.ps1 -CheckOnly

# 拉起缺失的本地组件；已运行的正确实例直接复用。
.\scripts\start-all.ps1

# 只处理后端（数据库与缓存必须可连接）。
.\scripts\start-all.ps1 -BackendOnly
```

启动器读取配置中的端口和数据库/缓存地址；数据库不可达时停止操作，不安装或重置数据库。现有本机`sub2-redis.exe`仅用于原配置127.0.0.1:6379，不将它称为生产Redis。端口被其他程序占用或无法确认进程归属时拒绝启动，不停止不相关进程。后端启动传入正确DATA_DIR，使用独立日志，并等待健康和版本返回；前端采用当前工作区Vite，不依赖调用命令时的目录。脚本退出后恢复临时环境变量。

## 已完成的本地0.2.1→0.2.4升级

仅本机的`output/upgrade-test-20260913`保存此次升级资料，其中有数据库、配置和会话信息，不在公开源码包中。`preflight.ps1`发现原始备份已存在即拒绝重新执行。`switch-current.ps1 -Action upgrade`已禁用重复执行，不能再次覆盖停服备份。

回滚前可以使用本机脚本的`-Action rollback -CheckOnly`：核对固定备份SHA256、现用程序/配置和原数据库目标，不停止服务也不恢复数据。实际回滚会覆盖升级后的业务写入，必须先评估数据，再显式传入`-ConfirmDataLoss`；该参数表达数据损失确认，不替代调用者获得操作授权。

回滚采用独占维护锁和唯一运行目录。停服后先备份当时的新数据、配置和程序，再使用`pg_restore --single-transaction --exit-on-error`恢复旧库。仅数据库恢复成功后才装回并启动旧程序；健康及版本校验通过才记录完成。恢复开始之前失败，可以恢复原运行程序；从数据库恢复开始起，任何失败都保留阶段记录并停止自动恢复，不能盲目拿旧程序启动未知数据库。状态记录位于独立rollback-runs目录，不覆盖既有升级证据。

新逻辑经过离线故障注入测试，没有在现用库执行新的回滚。最终停服备份已单独完整恢复至一次性数据库并核对余额、数量及四张业务表摘要；该临时库已删除，备份保持。
